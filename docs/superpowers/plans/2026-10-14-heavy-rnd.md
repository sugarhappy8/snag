# Heavy R&D Implementation Plan

> **For agentic workers:** use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Every classic company gets a Heavy R&D section: costly, slow, risky breakthrough products that, when they work, win share, lift demand for the whole trade, make the news, and force every rival to spend the same time (and, by tier, the same money) to catch up. Retired product lines never come back as R&D ideas.

**Spec:** `docs/superpowers/specs/2026-10-14-heavy-rnd-design.md` is the authority. Section numbers below (§3.x) refer to it.

**Architecture:** One new rules module `src/game/business/heavy-rd.ts` (records, curves, arrival, pulse, quote, start, advance) plus a catalogue `heavy-data.ts`. Existing files get thin hooks: `state.ts` (fields and loaders), `product-market.ts` (a `breakthrough` kind and `Field` support), `economy.ts` (`marketCtxFor` loads records and applies the pulse), `rd.ts` (retired list, `advanceRd` calls `advanceHeavy`), `products.ts` (skip retired names), `manage.ts` (menu rows, retire hook).

**Tech stack:** TypeScript (strict), Vitest. No new dependencies.

## Task 2: The catalogue (spec §3.2)

- [ ] **2.1** `heavy-data.ts`:
  ```ts
  export interface Breakthrough { name: string; first: number; note: string }
  export const BREAKTHROUGHS: Record<string, Breakthrough[]>   // keyed by industry id from industries.ts
  export function breakthroughsFor(industry: string): readonly Breakthrough[]
  ```

## Task 3: The engine, pure (spec §3.4, §3.5, §3.6)

**Files:** `heavy-rd.ts`, `product-market.ts`, `economy.ts`, `state.ts`, `test/heavy-engine.test.ts`.

- [ ] **3.1 Records.** In `heavy-rd.ts` (pure part first):
  ```ts
  export interface HeavyRecord { family: string; year: number; years: number; quality: number; cost: number; by: string }
  export function heavyKey(industry: string, market: string): string          // 'heavy.' + industry + '|' + market
  export function readHeavy(g: Pick<GameState,'flags'>, industry: string, market: string): HeavyRecord[]   // validated copy, max 12, newest last
  export function addHeavy(g: GameState, industry: string, market: string, rec: HeavyRecord): void       // dedupes by family (keeps the earliest), cap 12
  ```
  `readHeavy` validates every field (finite numbers, clamps: `year` 1800-2300, `years` 1-6, `quality` 0-100, `cost` 0-1e15, strings length-capped, `family` must be a known breakthrough name via `breakthroughByName`); anything invalid is dropped. A flag of the wrong type reads as empty.
- [ ] **3.2 Pure curves** in `heavy-rd.ts`: `heavyLevel(rec, year)` -> `{ exists, adoption, level }` (zero before `rec.year`; logistic over ten years to 1; from year 18 after launch declines toward 0.6; never below 0.005 once existing). `heavyArrival(rec, rival: {id: string; tier: string})` -> first year the rival offers the family, per §3.5 (`TIER_LAG`, `+ hash%2`; use the same `hashOf` the field uses; never earlier than `rec.year + rec.years`). `heavyVersionQuality(rec, rival)` per §3.5. `heavyPulse(records, year)` per §3.6 (cap +40%, finite, pure).
- [ ] **3.3 Kind.** `product-market.ts`: add `'breakthrough'` to `LineKind`; `KIND_WEIGHT.breakthrough = 1.6`, `KIND_COST.breakthrough = 1`. `state.ts`: add it to `Product['kind']` and to the validation in `lineExtras` (read it to see how the kind is whitelisted). Do not add a VARIANTS pattern: breakthrough lines always carry `family` and `kind` (set at launch, Task 4), and `infoOf` already trusts those.
- [ ] **3.4 Field.** `fieldOf(rivals, fringe, place, year, heavy?: readonly HeavyRecord[])`: include a signature of `heavy` in the cache key (`heavy.map(r => r.family + r.year + r.quality)`), pass it to `makeField`. In `makeField`'s per-family `get(family)`: when a record exists for `family`, build the `FamilyField` from the record (`exists`, `adoption`, `level` from `heavyLevel`; each rival's version from `heavyArrival` / `heavyVersionQuality`, `-1` before it arrives; the fringe offers it from `rec.year + ceil(rec.years * 2)`), and skip the real-history curve. Families without a record behave exactly as before (a test pins this on classic families).
- [ ] **3.5 Other readers.** Run `grep -rn "demandLevel\|demandTrend" src` and list every place that takes a line's family: `rd.ts standing()` and `rdQuote`'s `trend` must use the record for a breakthrough family (add `heavyLevelFor(family, records, year)` helper); the Products menu `lineSubtitle` trend. Anything else that only asks about classic families stays.
- [ ] **3.6 Economy.** `economy.marketCtxFor`: `const heavy = readHeavy(g, b.industry, marketKey(b))`; pass to `fieldOf`; `pot: ctx.pot * pulseScope * heavyPulse(heavy, year)` (keep the existing national multiplier). With no records the result is byte-identical to today (test: compare a ctx built before and after on a company with no flags).
- [ ] **3.7 Tests** (`test/heavy-engine.test.ts`): `readHeavy` hostile flags (wrong types, NaN, 100 records, unknown family, negative cost) -> clean and capped; `addHeavy` keeps the earliest per family; `heavyLevel` zero before launch, monotone up, plateau, decline; `heavyArrival` never before `year + years`, giant <= major <= mid <= small, deterministic; version quality never above the pioneer's; `heavyPulse` zero with no records, ramp over 3 years, cap 1.4 with 20 records, always finite; `fieldOf` with a record: before launch `exists` false, after arrival a giant offers it and a small rival does not yet; a `fieldOf` call with and without records on classic families returns equal numbers; `marketCtxFor` with no flags unchanged and with a record `pot` rises by the pulse; no `g.rng` use (state equal before/after).
- [ ] **3.8** Run `test/heavy-engine.test.ts`, every `test/product*.test.ts`, `test/competition*.test.ts`, `test/economy*.test.ts`; `npm run typecheck`. Commit: `feat: Heavy R&D engine: records, demand curve, rival arrival, market pulse`.

## Task 4: The project, the menu and the news (spec §3.3, §3.7, §3.9)

**Files:** `heavy-rd.ts`, `rd.ts`, `state.ts`, `manage.ts`, `history/market-events.ts`, `test/heavy-project.test.ts`.

- [ ] **4.1 Project fields.** `RdProject` gains `heavy?: true` and `cost?: number`; `projectExtras` (state.ts) loads them (heavy only when `x.heavy === true`; `cost` finite >= 0); `readProject`'s `years` clamp is 6 when `x.heavy === true`, else 4 as today.
- [ ] **4.2 Quote and rules** in `heavy-rd.ts`: `heavyCost(g, b)` = `roundBudget(8 * rdCost(b, classicIdeas(g, b)[0]))` (null when `classicIdeas` is empty); `heavyYears(b)` = `clamp(ceil(baseYears(industry) * 3), 4, 6)` (export `baseYears` from `rd.ts` or move it; do not copy it); `heavyOdds(g, b)` = `clamp(0.55 * launchP(g, b), 0.08, 0.6)`; `heavyQuality(g, b)` = `rdQuality(g, b, 2.5) + 14` capped at 97; `heavyOffers(g, b)` = the catalogue entries for `b.industry` with `first <= g.year`, passing `eraFits`, not retired, not already on sale or in development, in catalogue order. `heavyBlock(g, b, name)` returns the single reason string or null: not classic / no catalogue, a heavy project already running, cooldown (`b.heavyLast` year + 5 > `g.year`; `heavyLast?: number` is a new whitelisted optional `BizState` field), not enough cash (`cost + rdReserve(b)`, message says how much is missing), retired, era.
- [ ] **4.3 Start.** `startHeavy(g, a, b, name)`: re-check `heavyBlock`; take the cost from `b.cash` and add to `b.yearCosts` (same as `startRd`); push an `RdProject` with `heavy: true`, `cost`, `years`, `odds`, `quality`, `family: name`, `kind: 'breakthrough'`, `started`. Notice `R&D Underway` in the style of `startRd` (cost, years, odds). One `uid(g, 'rd')` call like `startRd`.
- [ ] **4.4 Advance.** In `advanceRd` (rd.ts), a project with `heavy: true` goes through `advanceHeavy(g, a, b, p, year)` when its progress completes (the progress tick itself is shared). `advanceHeavy`: roll `chance(g, p.odds)` (then `chance(g, 0.35)` for a hit, then `rand(g)` for the spread, in that order); on success create the `Product` (`launched: year + 1`, `family: p.name`, `kind: 'breakthrough'`, quality `+12` on a hit, spread +-10, brand `+12` hit / `+5` otherwise), `addHeavy(g, b.industry, marketKey(b), { family: p.name, year: year + 1, years: p.years, quality, cost: p.cost ?? p.budget, by: a.id })`, set `b.heavyLast = year`, push news (4.6). On a flop: brand `-6`, `b.heavyLast = year`, one line in the R&D Results notice, no news item. Ordinary projects keep exactly today's path.
- [ ] **4.5 Menu** (`manage.ts`, Products screen, after the project list): heading `Heavy R&D`; one action per `heavyOffers` entry named `heavy.${name}` with subtitle `${money(cost)} · ${years} years · ${pct odds} odds · rivals could follow about ${year + earliest lag}` (earliest lag from `heavyArrival` with a giant tier, the formula in one helper `heavyLead(rec-like)`), a `confirm` sentence repeating cost, years and odds, a `disabled` reason from `heavyBlock`. A running heavy project shows in the existing project list with years left (no new code beyond the label).
- [ ] **4.6 News.** On a successful launch: `log(g, `${company} launched ${name}.`, 'good')`; a modal notice queued with a deterministic id through the same queue pattern used in `yearly.ts` for event notices (read how it dedupes by id; title `${name}: a New Kind of ${trade}`, one short paragraph); one entry appended to the market-news list in `history/market-events.ts` (find the existing shape there; cap the list at 20 newest). When the first rival's `heavyArrival` year passes (checked in `advanceHeavy`'s sibling: a small `heavyArrivals(g, b, year)` called from `advanceRd` for every classic company, BEFORE its early return for companies with no projects, pure on the record, written once per record via a `reported` flag on the flag entry: add `rival?: string` to `HeavyRecord`, set when reported), one life-log line `"<rival> launches its own <name>."`.
- [ ] **4.7 Tests** (`test/heavy-project.test.ts`): cost is 8x the first classic's `rdCost`; years in 4-6; odds band; `startHeavy` takes exactly the cost and a second start is blocked (one active); blocked for cash with the missing amount in the message; cooldown blocks for five years; old save with an ordinary project still loads and a `years: 6` heavy loads while an ordinary `years: 6` clamps to 4; over many seeds `advanceHeavy` produces both a launch (record written, product has `kind: 'breakthrough'`, news and log present, `heavyLast` set) and a flop (money gone, brand down, no record, no news); the modal id is deterministic (running the same year twice does not queue it twice); the menu row exists, shows cost/years/odds, and is disabled with a reason when blocked; menu and quotes use no `g.rng` (state equal before/after) and render from a deep-frozen state.
- [ ] **4.8** Run `test/heavy-project.test.ts`, `test/heavy-engine.test.ts`, `test/heavy-data.test.ts`, `test/rd-retired.test.ts`, every `test/rd*.test.ts`, `test/board*.test.ts`, `test/save-schema.test.ts`, `test/voice-guards.test.ts`; `npm run typecheck`; `node scripts/voice-report.mjs --json`. Commit: `feat: Heavy R&D: start, risky launch, news, menu`.
