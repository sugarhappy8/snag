Do not re-export `hydrateSaves` from `save.ts` (keeps `save.ts` free of a new edge; `main.tsx` and tests import `save-hydrate.ts` directly).

**Behaviour.** The "legacy" record is the one in localStorage under `SAVE_KEY` (`'anotherlife.save.v1'`); the IndexedDB record lives under the same key name in the `saves` store (`save-backends.ts:95-96`), so "legacy" always means the localStorage copy.
1. Whole body in try/catch. On an unexpected error: `setSaveBackend(null)`, log with `console.error`, resolve `{ backend: 'local', source: 'none', fellBack: true, imported: false }`.
2. If `savedThisSession()` is true, change nothing and resolve with `skipped: 'already-saved'` (a second call, or a call after the first save, must never replace a newer in-memory save with an older stored one).
3. Pick the backend. `opts.backend` wins (then `setSaveBackend(opts.backend)`). Else `opts.idb === false` means localStorage (`setSaveBackend(null)`, `fellBack: false`). Else race `openAndRead()` against a `timeoutMs` timer (default 3000), where `openAndRead` is `idbSaveBackend(opts.factory, timeoutMs)` followed by `backend.read()` (`idbSaveBackend` has its own 3,000 ms timer for `open` only; a hung read has none, so the race is needed). On success `setSaveBackend(idb)`. On rejection or timeout: `setSaveBackend(null)`, `fellBack: true`, and an `abandoned` flag so a late open or read neither switches the backend back nor writes. After a fallback the active backend is the default localStorage one (`activeBackend()`).
4. Candidates. With an asynchronous backend: `{ from: 'idb', raw }` from the read and `{ from: 'legacy', raw }` from a fresh `localSaveBackend().read()` (null when empty or unreadable). With a synchronous backend: one candidate `{ from: 'local', raw }` read from the active backend. Diagnose each with `diagnoseRecord`.
5. Decide (this table is the contract):
   - A legacy candidate that is `newer`: do not use IndexedDB this page. `setSaveBackend(null)`, `protectNewerRecord(raw, version)`, `addSaveNotice({ id: SAVE_KEY, kind: 'newer', bytes: raw.length, version })`, then go straight to step 7 (the IndexedDB record, if any, stays untouched; outcome `backend: 'local'`, `source: 'none'`, `fellBack: false`).
   - An IndexedDB or local candidate that is `newer`: it stays in place and wins: `protectNewerRecord(raw, version)`, notice `{ id: SAVE_KEY, kind: 'newer', ... }`, cache left empty. A legacy candidate beside it is treated as a loser (below).
   - Otherwise the winner is the only `ready` candidate; with two `ready` candidates `newerOf` decides; with none there is no winner.
   - Every non-winning, non-empty candidate is a loser. Copy it with `quarantineRecord(activeBackend(), raw, kind, version)` where kind is `'stale'` for a `ready` loser and its own kind (`'damaged'`, `'tooOld'`) otherwise. Clear it from its store only after the copy is confirmed (legacy: `localStorage.removeItem(SAVE_KEY)`; local: `backend.remove()`; an IndexedDB loser is not removed at all when the legacy winner is imported, because the import write replaces it, and is `backend.remove()`d when nobody wins). When `quarantineRecord` returns null (five copies kept) the loser stays where it is; an IndexedDB or local loser then gets a notice `{ id: SAVE_KEY, kind }` (Download reads the main record, which is correct for it); a legacy loser gets no notice (Download of `SAVE_KEY` would read the IndexedDB record, which would mislead).
   - Winner `idb`: `primeCache(JSON.stringify(game))`. Winner `local` (synchronous backend): nothing to write, reads stay live. Winner `legacy` (IndexedDB active): import, below.
6. Import. `json = JSON.stringify(game)`; `record = await encodeSnapshotRecord(json)`; `await backend.write(record)`; `back = await backend.read()`; success only when `await decodeSnapshotRecord(back) === json`. The whole import has its own `timeoutMs` budget. On success: `primeCache(json)`, `localStorage.removeItem(SAVE_KEY)` (the legacy key goes only now), `imported: true`. On any failure, timeout, or mismatch: `setSaveBackend(null)`, `fellBack: true`, the legacy record untouched, so the player keeps playing from localStorage exactly as in v4.0.2.
7. Finally merge the copies already kept: `for (const n of await scanQuarantine(activeBackend(), diagnoseForScan)) addSaveNotice(n)` where `diagnoseForScan` maps `ready` to `{ kind: 'stale' }` and passes `newer`, `tooOld` (with `version`) and `damaged` through. This also lists the copies made in step 5, so step 5 adds no notice for them.
8. `source` is `'idb'`, `'legacy'`, `'local'` or `'none'` by where the playable game came from. `backend` is `activeBackendName()` at the end.

**Tests** (`test/save-hydrate.test.ts`; stub `localStorage` with `memoryLocalStorage()` from `test/save-kit.ts`; pass `factory: fakeIndexedDb(...)`; `resetSaveStoreForTests()` in `beforeEach`; build the current-shape save once in `beforeAll` with `createNewLife({ seed: 7, year: 2026 })` plus 5 `ageUp` calls, and the old shape from `test/fixtures/save-v1.json.gz`, so the file stays under a minute).

```ts

export interface TrapNode { readonly active: boolean }                       // is this tabbable the focused one
export interface TrapKey { readonly key: string; readonly shiftKey: boolean }
export type TrapMove = { readonly kind: 'pass' } | { readonly kind: 'focus'; readonly index: number } | { readonly kind: 'container' }
export function trapFocus(nodes: readonly TrapNode[], key: TrapKey): TrapMove

export const TABBABLE_SELECTOR: string
export interface TabCandidate { readonly tag: string; readonly disabled: boolean; readonly tabIndex: number | null; readonly hidden: boolean; readonly inert: boolean; readonly type?: string; readonly hasHref?: boolean; readonly editable?: boolean }
export function isTabbable(c: TabCandidate): boolean

export interface TreeAccess<N> { parentOf(n: N): N | null; childrenOf(n: N): readonly N[]; exempt(n: N): boolean }
/** Siblings of `dialog` and of each of its ancestors up to `root`: everything that must go inert. Root and ancestors are never included. */
export function isolationTargets<N>(dialog: N, root: N, tree: TreeAccess<N>): N[]

/** First candidate that `usable` accepts, else null. Used for the focus restore chain. */
export function restoreTarget<E>(candidates: readonly (E | null)[], usable: (e: E) => boolean): E | null

// modal.ts
export interface ModalEnv<E> {
  readonly root: E
  readonly tree: TreeAccess<E>
  active(): E | null
  contains(outer: E, inner: E): boolean
  tabbables(container: E): readonly E[]
  focus(e: E): void
  setInert(e: E, on: boolean): void
  usable(e: E): boolean       // connected, not disabled, not inert, not <body>
  isBody(e: E): boolean
  home(): E | null            // the [data-focus-home] element
}
export interface ModalHandle {
  handleKey(e: { key: string; shiftKey: boolean; preventDefault(): void }): void
  /** Focus the container when focus was lost (activeElement is body or detached) and this is the topmost modal. */
  refocus(): void
  close(): void
}
export function openModal<E>(env: ModalEnv<E>, container: E, opener: E | null): ModalHandle
export function isModalOpen(): boolean
export function domModalEnv(): ModalEnv<HTMLElement> | null      // null without a document (server render)
export function useModal(ref: React.RefObject<HTMLElement | null>): void
// ModalSurface.tsx
export interface ModalSurfaceProps { role: 'dialog' | 'alertdialog'; label?: string; className?: string; children: ReactNode }
export function ModalSurface(props: ModalSurfaceProps): ReactElement
```

**Behaviour.**
1. `trapFocus`: key other than `Tab` is `pass`. No nodes is `container`. Let `i` be the index of the active node (-1 when none). `i === -1`: Tab focuses index 0, Shift+Tab the last. Tab on the last node (also a single node) focuses 0. Shift+Tab on index 0 focuses the last. Anything else is `pass` (the browser moves focus inside the trap).
2. `isTabbable`: false when `disabled`, `hidden` or `inert`; false when `tabIndex` is a number below 0; true for `button`, `select`, `textarea`; `input` unless `type === 'hidden'`; `a` and `area` only with `hasHref`; `editable`; otherwise true only when `tabIndex` is a number at or above 0. `TABBABLE_SELECTOR` is `'a[href], area[href], button, input, select, textarea, summary, [contenteditable=""], [contenteditable="true"], [tabindex]'` (the pure filter does the rest).
3. `isolationTargets`: walk from `dialog` up to `root`; at each step add the siblings of the current node (children of its parent other than itself) that `tree.exempt` does not exempt; stop at `root` or when a parent is null (a dialog outside `root` isolates what it can).
4. `openModal(env, container, opener)`:
   - Register in a module-level stack; `isModalOpen()` is true while the stack is not empty.
   - Isolate: for each target, a module-level `WeakMap` reference count goes up; on 0 to 1 call `env.setInert(t, true)`. Nested modals therefore keep the lower layers inert until the last one closes.
   - If the active element is not inside `container`, `env.focus(container)`. (React `autoFocus` children have already taken focus by then and are left alone.)
   - `handleKey`: only for the topmost modal; compute `nodes = env.tabbables(container).map(el => ({ active: el === env.active() }))`; `trapFocus`; for `focus` call `preventDefault` and `env.focus(nodes index element)`; for `container` call `preventDefault` and focus the container.
   - `refocus`: topmost only; when `env.active()` is null, a body, or not inside `container`, focus `container`.
   - `close`: pop the stack; decrement counts (on 1 to 0 `setInert(t, false)`) BEFORE restoring focus, because an inert element cannot take focus; then, only when focus was inside the container or on the body, focus `restoreTarget([opener, the next topmost container, env.home()], env.usable)`. It never steals focus that already moved to another modal.
5. `domModalEnv`: root is `document.getElementById('root') ?? document.body`; `tree` uses `parentElement` and `Array.from(parent.children)`; `exempt` is `el.hasAttribute('data-modal-exempt')` or a `SCRIPT`, `STYLE`, `LINK`, `TEMPLATE` tag; `tabbables` is `querySelectorAll(TABBABLE_SELECTOR)` filtered by `isTabbable({ tag, disabled, tabIndex: el.getAttribute('tabindex') === null ? null : el.tabIndex, hidden: el.hidden || el.getClientRects().length === 0, inert: el.closest('[inert]') !== null, type, hasHref, editable: el.isContentEditable })`; `setInert` toggles the `inert` attribute; `home` is `document.querySelector('[data-focus-home]')`; `usable` rejects disconnected, `disabled`, `closest('[inert]')` and `document.body`.
6. `useModal(ref)`: capture the opener during the first render with `useState(() => (typeof document === 'undefined' ? null : document.activeElement))` (it has to be read before React `autoFocus` moves focus, which happens during commit); in an effect with no dependencies other than mount: `openModal`, add a capturing `keydown` listener on `document` that calls `handle.handleKey`, and on cleanup remove it and call `handle.close()`; a second effect with no dependency array calls `handle.refocus()` after every render (a menu level change removes the row that had focus); keep the handle in a `useRef` so both effects share it. Nothing runs on the server.
7. `ModalSurface` renders `<div ref className role aria-modal="true" aria-label tabIndex={-1} onClick={(e) => e.stopPropagation()}>` and calls `useModal(ref)`. The stopPropagation matches what `Sheet`, `PopupFrame` and the screen dialogs do today.

2. `isTabbable` table: button, disabled button, `tabindex="-1"`, `tabindex="0"` div, hidden input, anchor with and without href, inert subtree, `hidden`.
3. `isolationTargets` over a plain-object tree: dialog nested two deep returns exactly the siblings along the path, not the ancestors, not the root; an exempt sibling is skipped; a dialog directly under the root; a dialog outside the root.
4. `restoreTarget` picks the first usable candidate, skips null, returns null when none.

## R1-A8 The `lazyView` kit and the lazy-zone test

**Roadmap items.** G.14 (the chart kit and the palette load lazily), D.2, D.11 item 12.

**Files.**
- Create `src/ui/lazy/lazyView.tsx`.
- Modify `src/App.tsx` (one call in `startup()`, line 15).
- Modify `src/ui/styles/global.css` (`.lazy-box`, `.lazy-failure`; after the A5 block or at the end).
- Create `test/lazy-kit.ts` (a static-import scanner used only by tests).
- Create `test/lazy-view.test.ts` and `test/lazy-zones.test.ts`.

**Why not `React.lazy`.** `renderToStaticMarkup` cannot wait for a lazy component, so every existing test of a consumer (for example the Annual Report) would see only a Suspense fallback. `lazyView` caches the loaded module and renders it synchronously once loaded, so a test awaits `View.preload()` and then renders the real thing.

**Interfaces.**
```ts
export type LazyPhase = { kind: 'idle' } | { kind: 'loading' } | { kind: 'ready' } | { kind: 'failed'; attempts: number }
export type LazyEvent = { kind: 'start' } | { kind: 'loaded' } | { kind: 'error' } | { kind: 'retry' }
export function lazyStep(phase: LazyPhase, event: LazyEvent): LazyPhase
export interface LazyOwnProps { /** Shown while loading and after a failed load: the old text rows. */ fallback?: ReactNode }
export interface LazyView<P extends object> {
  (props: P & LazyOwnProps): ReactElement | null
  /** Starts the load once; resolves true when the module is ready, false when it failed. Never rejects. */
  preload(): Promise<boolean>
  isReady(): boolean
  readonly displayName: string
}
export function lazyView<P extends object>(name: string, load: () => Promise<{ default: ComponentType<P> }>): LazyView<P>
export interface LazyFailureProps { attempts: number; onRetry(): void; onReload(): void }
export function LazyFailure(props: LazyFailureProps): ReactElement
/** Load every registered view when the browser is idle; skipped on Save-Data or a 2g connection. */
export function prefetchLazyViews(): void
/** Tests only: forget every registered view and cached module. */
export function resetLazyViewsForTests(): void
```

**Behaviour.**
1. `lazyStep`: idle + start is loading; loading + loaded is ready; loading + error is failed with attempts + 1; failed + retry is loading; ready ignores everything.
2. `lazyView` keeps a module-level cache per view. Rendering when the module is loaded: `<Loaded {...props} />`. Otherwise it renders `props.fallback ?? <div className="lazy-box" aria-busy="true" />` and an effect calls `preload()` then re-renders. On failure it renders the fallback and `LazyFailure` below it: "This view didn't load." with a "Try again" button for the first failure (calls `preload()` again) and a "Reload" button from the second failure on (`flushSave()` then `location.reload()`; the save is written on every commit, the flush makes sure). The fallback is the old text rows, so a failed chunk degrades to today's UI.
3. Every `lazyView(...)` call registers the view in a module-level list for `prefetchLazyViews`. `prefetchLazyViews` uses `requestIdleCallback` with a 2,000 ms `setTimeout` fallback, loads the views one at a time, and does nothing when `navigator.connection?.saveData` is true or `effectiveType` is `slow-2g` or `2g`. Call it once from `startup()` in `App.tsx`, so the first chart open is usually instant.
4. Failure cases that matter: after a deploy the old hashed chunk is gone and `wrangler.jsonc` serves `index.html` for unknown paths (`not_found_handling: single-page-application`), so a long-open tab gets an HTML response for a module URL; the dynamic import rejects and the path above applies. Do not auto-reload.

**Contract for the other tracks.** Charts (G.2) creates `src/ui/charts/ChartView.tsx` (default export, renders a `ChartSpec` by kind) and `src/ui/charts/lazy.tsx` exporting views made with `lazyView`; every consumer (`AnnualReport.tsx`, cockpits, `ProfileSheet.tsx`) imports from `lazy.tsx` only, with `fallback` set to its text rows. Navigation (R1-N6) creates `src/ui/nav/lazy.tsx` exporting `LazyPalette` over `src/ui/nav/Palette.tsx` (a default export) and keeps `searchIndex.ts` reachable only from the palette zone of test 9. Header buttons, pins, recents and the Ctrl+K handler stay static. Navigation's cockpits import the chart kit only through `src/ui/charts/lazy.tsx` (`LazyChartView`, `LazyKpiTile`, `LazySparkline`) and use no `React.lazy`.

**Tests.**
`test/lazy-view.test.ts`:
1. `lazyStep` table, including failed + retry and ready absorbing.
2. Before `preload`, `renderToStaticMarkup(createElement(View, { fallback: createElement('p', null, 'text rows') }))` contains the fallback and no real content; without a fallback it contains `lazy-box` and `aria-busy`.
3. After `await View.preload()` with a loader resolving a dummy component, the same render contains the dummy's markup and `isReady()` is true; the loader ran once for three `preload()` calls.
4. A loader that rejects: `preload()` resolves false, `isReady()` false, render shows the fallback; a later `preload()` with a loader that works succeeds (retry).
5. `renderToStaticMarkup(createElement(LazyFailure, ...))` shows "Try again" at attempts 1 and "Reload" at attempts 2.
6. (After `resetLazyViewsForTests()` in `beforeEach`.) `prefetchLazyViews` with a stubbed `navigator.connection` `{ saveData: true }` loads nothing; with `{ effectiveType: '4g' }` and a stubbed `requestIdleCallback` it loads each view once, in order.

## Plan vs code (differences from the roadmap, verified by reading the code)

1. **`aria-modal` on `PopupFrame`.** D.8 says both `Sheet.tsx` and `PopupFrame` get `aria-modal`. `PopupFrame` already has `aria-modal="true"` (`src/ui/components/Dialogs.tsx:33`); only `Sheet` (`Sheet.tsx:18`, `role="dialog"` alone) lacks it. A5 adds it to `Sheet` and to the two screen dialogs (`SettingsScreen.tsx:65`, `RibbonsScreen.tsx:114`, which the roadmap does not mention).
2. **"`inert` on the background root".** There is no single background root. Sheets, popups and the page content are siblings inside `.game` (`GameScreen.tsx:99-132`), and the save banner sits beside `.game` in `.app` (`App.tsx:47-51`). The plan inerts the siblings along the path from the dialog up to `#root` (`isolationTargets`), with reference counts for stacked dialogs and an exemption attribute for live regions (save banner, toast). A portal would be the usual fix but `react-dom/server` (`renderToStaticMarkup`, used by the tests) does not support portals.
3. **Opener capture.** Focus restore needs the opener, and React `autoFocus` (OK buttons in `ModalHost.tsx:92`, `Dialogs.tsx:89` and `:117`) moves focus during commit, before any effect runs. The hook reads `document.activeElement` in a `useState` initializer during the first render instead.
4. **Header contrast.** D.8 says the header text on the gradient start is 3.64:1 and is fixed by darkening `--header-from`. Confirmed for white on `#2a86f0` (3.64), but darkening only the start leaves the opacity-faded year, label and role text, the mint money (3.17 on the start, 4.23 on the end) and the pink negative money (2.38 and 3.17) below 4.5, and the dark theme's negative money is 3.97 on its own start. A7 therefore changes both ends, replaces the opacity text with solid tokens and recolors the negative money, and tests all of them. There is no `[data-theme]` attribute in this repo (dark mode is `@media (prefers-color-scheme: dark)` only), so the contrast test overlays that block as R0-11 does.
5. **Targets.** D.8 names the header icons (32px, `global.css:726`). `.sheet-nav` (40px, `global.css:501`) and `.al-back` (40px, `screens.css:56`) are also under 44, and `.hdr-top` has `min-height: 32px` (`global.css:701`). All are moved to a `--target: 44px` token.
6. **Focus ring.** Not in the roadmap. The global `:focus-visible` outline is `color-mix(in srgb, var(--blue) 55%, transparent)` (`global.css:198`), about 2.2:1 on white and invisible on the blue headers. A7 replaces it with a solid token (3:1 or better on every surface, tested).
7. **K.5a is bigger than "wire two functions".** `idbSaveBackend` (`save-backends.ts:101`) and `setSaveBackend` (`save-store.ts:96`) have no production caller, as the roadmap says, but also: no `hydrateSaves` exists anywhere (grep), so for an asynchronous backend `readRecord()` (`save-store.ts:212`) answers from a cache that nothing fills at boot; `scanQuarantine` and `protectNewerRecord` have no production caller; `getSaveStatus`, `subscribeSaveStatus` and `SaveNotice` have no UI consumer. `docs/superpowers/plans/2026-10-14-save-safety.md` Tasks 6 to 8 specify exactly these and were never built; digest K says the same ("no `hydrateSaves`"). A1 to A3 build them, adapted to the current code (the hydrate lives in its own file; notices subscribe to the save status directly because `test/screens.test.ts` mocks the store with a fixed export list).
8. **The 3,000 ms timeout.** `idbSaveBackend(factory, timeoutMs = 3000)` (`save-backends.ts:101`) times out only the `open`; a read that never completes has no timeout (the fake has `hang: 'read'` for this). The boot needs its own race around open plus first read, and around the import write.
9. **Banner never shows for IndexedDB failures.** `ui/store.ts` sets `saveError` only from `saveGame`'s return (`:350`, `:310`), and with an asynchronous backend `saveRecord` returns true even if the write fails later (`save-store.ts:185`). A2 mirrors `getSaveStatus().persistFailed` into `saveError` and makes the Time Machine jump wait for `flushSave()`. Not in the roadmap.
10. **"Reads the legacy key once and migrates it".** The IndexedDB record uses the same key name `anotherlife.save.v1`, so "legacy" means the localStorage copy. The v2.5 design deletes it only after a read-back check and lets IndexedDB win when both exist. A1 keeps that, with two additions that close data-loss paths: a hung IndexedDB makes the page play from localStorage, so on the next boot both stores can hold the same life; the later `(year, age)` of the same `lifeId` wins instead of IndexedDB blindly; and a `newer` legacy record keeps the page on localStorage.
11. **Boot cost.** `main.tsx` renders synchronously today (13 lines, `createRoot(...).render` at module load). A hung database now delays the first paint by up to 3 seconds; A2 adds an inline splash in `index.html`.
12. **G.14 wording.** "Load lazily via React.lazy". `React.lazy` makes every `renderToStaticMarkup` test of a consumer see only the Suspense fallback, so A8 uses its own `lazyView` (dynamic `import()` plus a cache, a preload hook for tests, a failure path). The roadmap does not mention the failure path; `wrangler.jsonc` has `not_found_handling: single-page-application`, so a stale hashed chunk after a deploy returns `index.html` and the import rejects.
13. **Test file type.** `vite.config.ts` includes only `test/**/*.test.ts`; there are no `.tsx` tests. All component tests here use `createElement`.
14. **Existing fakes.** The roadmap says "tests with a fake IDBFactory in node". `test/save-kit.ts` already has `fakeIndexedDb` (options `failOpen`, `hang: 'open' | 'read'`, `failWrite`, `corruptReadback`), `memoryLocalStorage` and `controlledBackend`. Only a `slowOpen` option is added.
15. **Fixture.** D.11 item 11 says "a v4.0.2 localStorage save". Only `test/fixtures/save-v1.json.gz` (a v2.4.0 save, schema 1) exists. A1 tests use it plus a save generated in-test by `createNewLife` and `ageUp`, which has the v4.0.2 shape; a committed v4.0.2 fixture (220 KB gzip for the v2.4.0 one, larger now) belongs to the Charts series tests (D.3) and can be added to the `it.each` of A1 case 5 if it exists.
16. **Wrangler/Vite chunking.** Vite is 8.3.2 (Rolldown); dynamic imports split without configuration. `build.chunkSizeWarningLimit` (`vite.config.ts:11`) stays 8000.
17. **Quarantine edge.** With five copies kept, a losing legacy record stays in localStorage; if the player then abandons the IndexedDB life, the next boot would find a lone legacy record and import it. Accepted (it needs five kept copies, both stores present, and an abandon); noted in the docs.
18. **Rollback.** After the import the legacy key is gone, so an older build cannot see the save until the new build returns (design section 13.5 and the v2.5 spec risk list). Say so in the release notes.
