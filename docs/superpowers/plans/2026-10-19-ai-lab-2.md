**Goal:** An AI lab sees honest per-capability benchmark standing against modeled rival labs by year, can fund research that moves one capability, earns recorded firsts, and earns demand from its lead over the best rival.

**Architecture:** A pure, roster-free layer (`scorecard.ts`, `ai-bench-data.ts`, `ai-bench.ts`) holds the eight capabilities, ratings, benchmark generations and the model-rating formula. A second layer (`ai-bench-market.ts`) builds the rival board from the existing rosters and answers `labStanding`, `labLead` and `bestRival`. `trainWin`, `competitiveness`, research tracks, releases, claims and the Benchmarks menu read those functions, so hints, demand and text share one source. New saved state is optional and normalized by `readTech`, `readModel` and `readAiFirsts`.

**Tech Stack:** TypeScript (strict, `noUnusedLocals`), Vitest, no new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-19-ai-lab-2-design.md` (release 2 of 8). Release 1: `docs/superpowers/specs/2026-10-19-tech-waves-design.md` (section 11 wins) and `docs/superpowers/plans/2026-10-19-tech-waves.md`. Where this plan and the spec differ, the plan wins. ## Decisions made while planning (cited as P1 to P9)

- P1 Files. `business/ai-bench-claims.ts` holds `readAiFirsts` and `benchWorldFlags` (Task 3) and `claimFirsts` (Task 7). `benchYear`, `BestRival`, `leadTier` and `LEAD_ENDING` live in the roster-free `ai-bench.ts`, so `trainWin` can use them without a cycle. `deeptech-bench.ts` (new, Task 7, extended in Task 8) builds every line and may import the roster code. A scratch probe showed `deeptech-data.ts` importing `assets.ts` (for `seeded`) loads without a cycle error.
- P2 Catch-up is a uniform lift. For each open capability, the floor is the largest `rating - 70` over every unheld rated model `m` with `m.year + lag <= year` (lag 2, or 1 when `m.open`). Every rival's rating in that capability rises by `max(0, floor - leader rating)`. The spec's "best released model" is read as every released model, so a newer model never undoes an older catch-up. The lift lives in `bestRival`, `labLead` and `labStanding`; `capFrontier` stays pure in `(fam, cap, year)`.
- P3 Units. Capability and overall `ScoreRow`s are benchmark scores (0 to 99) on that year's test. `lead` is in composite rating points. `trend` compares the lab's best model as of `year - 1` with its best as of `year`, both on `year`'s test, so a retired generation is not a fall. A missing rating counts as 0.
- P4 `labLead(fam, t, year): number | null` is the cheap read (no rows) that `competitiveness`, `techPremium` and the hype tiers use, and `labStanding().lead` equals it.
- P5 `compositeRating` and `modelScore` weight by `capWeight(cap, year)` (rescaled over the capabilities open that year); `modelStrength` uses the base weights, so models from different years compare by rating.
- P6 The lab menu stops listing track programs in Task 8, when Benchmarks exists to point to. Until then they show as ordinary program rows.
- P7 Sparks: the Overall row carries the composite score series; each capability row carries that capability's own score series.
- P8 `RATING_OFFSET` starts at 320, not the spec's 330. A planning probe on family `'test-life'`, year 2026, roll 0.5 with the seeded specialty gave typical 0.945, maxed 1.478, weak 0.323 at 330 (typical just under the 0.95 floor) and 0.997, 1.486, 0.376 at 320. If a band still fails, change only `RATING_OFFSET` (steps of 5) or `LEAD_DIVISOR`.
- P9 Board size. The probe measured 25 to 27 labs in 2026 (12 or 13 in 2013, 21 in 2020), so tests use 15 to 32 for 2026, not the spec's 15 to 25. `capBest` returns whole numbers (the interpolation is rounded) so every rating is an integer.

import { describe, expect, it } from 'vitest'
import { scoreRow, scoreText } from '../src/game/business/scorecard'

const F = [78, 75, 70, 66, 64, 60, 55, 44]
describe('scoreRow', () => {
  it('ranks among the field and yourself, with the market as the mean of everyone else', () => {
    expect(scoreRow('coding', 'Coding', 'score', 71, F)).toEqual({ id: 'coding', label: 'Coding', unit: 'score', mine: 71, market: 64, best: 78, rank: 3, of: 9, trend: 1 })
    expect(scoreRow('x', 'X', 'u', 90, F)).toMatchObject({ best: 90, rank: 1, of: 9 })
    expect(scoreRow('x', 'X', 'u', 70, [70, 70, 60])).toMatchObject({ rank: 1, of: 4 })   // ties share the better rank
    expect(scoreRow('x', 'X', 'u', 5, [])).toMatchObject({ market: 0, best: 5, rank: 1, of: 1 })
  })
  it('drops non-finite field entries, reads a non-finite mine as 0 and leaves the field alone', () => {
    expect(scoreRow('x', 'X', 'u', NaN, [NaN, Infinity, -Infinity, 50])).toEqual({ id: 'x', label: 'X', unit: 'u', mine: 0, market: 50, best: 50, rank: 2, of: 2, trend: 0 })
    const f = Object.freeze([3, 1, 2]); expect(() => scoreRow('x', 'X', 'u', 2, f)).not.toThrow(); expect(f).toEqual([3, 1, 2])
  })
  it('trend is 1 above prior + 0.5, -1 below prior - 0.5, else 0; a missing or non-finite prior is 0', () => {
    const t = (m: number, p?: number) => scoreRow('x', 'X', 'u', m, [], p).trend
    expect([t(70.5, 70), t(70.51, 70), t(69.5, 70), t(69.49, 70), t(5), t(5, NaN), t(0.4)]).toEqual([0, 1, 0, -1, 1, 1, 0])
  })
})
describe('scoreText', () => {
  it('prints the sample line, rounds by default, takes fmt, and names an empty market without opening on Nobody', () => {
    expect(scoreText(scoreRow('coding', 'Coding', 'score', 71, F))).toBe('Coding 71. Market 64, best 78, rank 3 of 9.')
    expect(scoreText(scoreRow('coding', 'Coding', 'score', 71.4, [64.5, 60.2]))).toBe('Coding 71. Market 62, best 71, rank 1 of 3.')
    expect(scoreText(scoreRow('p', 'Price', 'usd', 1200, [900, 1500]), (n) => `$${n}`)).toBe('Price $1200. Market $1200, best $1500, rank 2 of 3.')
    const empty = scoreText(scoreRow('coding', 'Coding', 'score', 71, []))
    expect(empty).toBe('Coding 71. The market has no figures.'); expect(empty).not.toMatch(/^Nobody|[\u2014\u2013]/)
  })
})
