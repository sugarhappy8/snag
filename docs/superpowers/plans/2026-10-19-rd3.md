# R&D 3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every product company the R&D that sits between a new product line and a breakthrough: fixed-price Operations R&D that cuts unit cost, lifts output and wins repeat customers, an R&D tax credit and grants, a research team, patents with licensing, and rivals whose versions improve over the years.

**Architecture:** One optional record, `BizState.lab`, read by `readLab` and replaced whole by `saveLab`, holds programs, levels, scientists, patents and a four-year ledger. Pure rules and values live in `lab-rules.ts`, bookings and actions in `lab-year.ts`, copy in `lab-text.ts`, the screen in `lab-menu.ts`. Effects join the existing readers: `businessEffects` (cost, capacity, demand), `launchP` and `rdSlots` (team), `fieldOf` and `makeField` (patent shield, rival rise), `valuationOf` and `statementLines` (ledger). A trade tier table and a per-trade ageing table come first.

**Tech Stack:** TypeScript (strict, `noUnusedLocals`, `noUnusedParameters`; `tsconfig` includes `test`, so tests are typechecked too), Vitest, no new dependencies, no `src/ui` change.

**Spec:** `docs/superpowers/specs/2026-10-19-rd3-design.md` ("S4.4" means its section 4.4). Executors read both. The spec and this plan agree on every name and signature; if an edit ever makes them differ, this plan wins and the spec is fixed to match.

**The tree this plan is applied to is not the tree it was written on.** It was written against main v3.0.0. The tree it lands on will contain other releases' changes (release 1 tech waves and others: a wave hook in `advanceHeavy`, `BizState.wave`, new code in `yearly.ts`, `product-market.ts`, `economy.ts`). Every line, anchor and neighbour named below is from v3.0.0. Re-read the actual code of every file before editing it, and keep each edit its own additive hunk.

**Order and models:** One task at a time, in order: Tasks 2 to 6 share `lab-state.ts`, `lab-year.ts`, `lab-rules.ts`, `lab-menu.ts`, `lab-text.ts` and `test/lab-kit.ts`, and Task 7 needs the `market` parameter that Task 5 adds. Per `CLAUDE.md`, implement and review every task with Sonnet; use Opus only for Task 5 after Sonnet has failed on it, one Opus run at a time.

## Global Constraints

- Saves: `SAVE_SCHEMA` stays 2 and `BIZ_VERSION` stays 2. The only new saved state is `BizState.lab?: Json`, optional, read by `readLab`, written whole by `saveLab`, never mutated in place. No world flag, no `RdProject` or `Product` field.
- Determinism: `g.rng` is drawn only by `advanceLab` (`chance(g, odds)`, once per finished program in track order cost, yield, quality). Menus, quotes, hints, `riseOf`, `shieldsOf`, `patentValue` and `bestLabMove` use stored state and hashes only. No `Math.random`. The one exception is the hired CEO's `judge` (it draws one `g.rng` number per call): `bestLabMove` calls it only for a candidate whose exact value is above 0, so a hired-CEO save with nothing worth starting draws exactly what it drew in v3.0.0.
- Prices are fixed per trade and program: `rdSiteScale(b)` times `RUNG_X` `[1, 2.2, 4.5]`. Nothing scales with cash, sales or valuation (spec 2026-10-12 section 1).
- Money: credit, grant and royalty are `b.cash += x; b.yearIncome += x`; payroll, fees and prices are `b.cash -= x; b.yearCosts += x`. Every amount has a `LabRow` field and a statement line, and `bookYear` counts it without moving cash again.
- Caps: `LAB_CREDIT_CAP` 250,000; credit rate `clampN(RD_CREDIT[country] ?? 0, 0, 0.5)`; grant `min(max, price x min(share, 0.5 - rate))`; a level is at most .95 and fades x.95 a year; each win on a track is worth x.8 of the last (`runs` capped at 12); rival rise at most 8 points; patent book `IP_SHARE` .6 of a fixed price, x.9 a year.
- Bounds: 3 programs (one per track), 6 scientists, 6 patents, 40 filed names, 4 ledger rows, 9 `done` ids, family names at most 80 characters.
- Authorization: `doOps`, `doPatent`, `doLicense`, `doHire` and `doRelease` re-find the live company and check `manageBlock`, their own `*Block` reason and (for any spend) `boardAllows(g, cur, b, { kind: 'capex', by: 'owner', amount, gain: max(0, win / 5), label })` themselves, so a direct call, a restored menu or an older save cannot skip them. `win` is the gross expected win before its price, as ordinary R&D has it (`rdValue.value + budget`): an Operations program `opsValue + price`, a patent `patentValue.value + fee`, a hire `teamValue.gain`; a release asks with `gain` 0 (it spends the fee), and a license spends nothing, so it asks no vote.
- Idempotence: `bookLabYear` is guarded by `lab.booked`, `advanceLab` by `lab.stepped`; levels and shields fade by year arithmetic, not by a step.
- Purity: menus, subtitles, hints and quotes never write state or draw `g.rng`; `readLab` returns a shared read-only object (cached by identity), writers use `draftLab` then `saveLab`.
- Text: `docs/VOICE.md`; caps log 90, outcome and notice 120, tooltip 120, scene 140 (no scene is added), measured on the static text with `${}` counting zero, and every template also stays inside the aims (log 60, outcome 100, tooltip 100: `unitFlags` in `scripts/voice/rules.mjs` returns no flag, as `test/heavy-voice.test.ts` checks for Heavy R&D); contractions; no em-dash or en-dash character anywhere, in code, tests or docs (`voice-guards` caps em-dashes at 24 and it is exactly 24: never type U+2014 or U+2013); `${}` counts zero. All new copy is built by functions in `lab-text.ts` (money formatted at call time, never at module load: `test/currency-static.test.ts`).
